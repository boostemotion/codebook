# 安全模型

Cipherbook 处理高价值凭据。本文说明已经实现的保护、明确不覆盖的风险，
以及快速解锁和局域网同步的安全取舍。

> 本项目尚未提供可公开验证的独立安全审计或渗透测试报告。不要把“使用了加密算法”
> 等同于“已经通过安全认证”。

## 主要资产

- 用户主密码；
- 密码库 DEK 和 KEK；
- 登录项中的账号、密码、网址、备注和 TOTP 密钥；
- Bitwarden 明文交换文件；
- 局域网设备身份、访问 token 和配对记录；
- 快速解锁缓存和冷启动偏好。

## 静态数据保护

密码库保存在应用支持目录的 `vault.pwv`。核心密钥链是：

```text
主密码 -> Argon2id -> KEK
随机 DEK -> 由 KEK 包装
VaultData -> 由 DEK + XChaCha20-Poly1305 加密
```

默认 Argon2id 参数为 64 MiB 内存、3 次迭代和并行度 1。KEK 和 DEK 都是 256 位。
文档使用认证附加数据（AAD）绑定密码库 ID、key generation 和 revision。

修改主密码会重新生成盐、KEK 和 DEK，而不是只替换一个口令字段。主密码遗失后没有恢复后门，
只能依靠已知密码、已有导出文件或用户自行保存的备份。

## 会话与锁定

- 解密数据只存在于当前进程内存。
- 锁定会清空控制器中的条目、DEK 和 KEK。
- 自动锁定时间可选 1、2、5 或 15 分钟，默认 2 分钟。
- 应用进入后台或窗口隐藏后会主动锁定。
- 复制密码后 30 秒会尝试清空剪贴板；锁定或退出时也会尝试清理本应用写入的内容。
- Android 设置 `FLAG_SECURE`，阻止常规截图和最近任务缩略图。
- Android Manifest 设置 `allowBackup="false"`，避免系统云备份复制应用私有数据。

进程内存仍可能受到恶意调试器、内核级恶意软件、注入或内存转储影响。应用无法防御已经取得
操作系统管理员/root 权限的攻击者。

## 快速解锁

快速解锁缓存的是经过平台保护的 KEK，不保存主密码。

### Windows

- 缓存文件位于当前用户的 LocalAppData。
- 缓存使用当前 Windows 用户范围的 DPAPI 保护。
- 读取缓存前调用 Windows Hello 验证。
- 如果 Windows Hello 取消、失败或不可用，快速解锁返回失败，必须使用主密码。
- “冷启动直接快速解锁”默认关闭；开启后仍要求 Windows Hello 成功。

DPAPI 不能抵御已经完全控制当前 Windows 用户会话的攻击者。系统账户被入侵时，
密码库的本地保护边界也会降低。

### Android

- 包装密钥位于 Android Keystore。
- 使用 AES-GCM，并要求强生物识别认证。
- 生物识别录入发生变化时，旧 Keystore 密钥会失效。
- 设备 PIN、图案或弱生物识别不用于快速解锁。
- 快速解锁失败时不会回退到明文 DEK 或主密码缓存。

“冷启动直接快速解锁”只保存布尔偏好。关闭快速解锁时会删除平台包装密钥并关闭该偏好。

## 局域网同步

局域网同步只在应用解锁并主动开启分享时运行。安全边界包括：

- UDP 仅用于局域网发现；
- 发现信息包含设备名、密码库 ID、版本、KDF 参数和 challenge，不包含主密码；
- 主密码验证通过 HMAC-SHA256 challenge proof 完成，主密码本身不发送；
- 传输内容是已经加密的 `.pwv` 文档；
- 已配对设备使用随机 device ID 和 access token；
- 请求有超时和 16 MiB 文档大小上限；
- 锁定或进入后台会停止 HTTP 分享与发现。

传输层是局域网 HTTP，因此同网段观察者可能看到设备地址、端口和协议元数据。
应用依赖密码库自身的加密和 HMAC 认证保护内容，不应把端口映射到公网，也不应在不可信公共 Wi-Fi
上执行同步。当前实现没有证书固定、跨公网穿透或中心服务器吊销机制。

## Bitwarden 数据交换

Bitwarden JSON/CSV 交换文件是明文凭据：

- 导出前有二次确认；
- 文件可由任何获得它的人直接读取；
- 不应提交到 Git、云盘公开目录、聊天记录或工单；
- 导入目标管理器后应立即删除；
- `.pwv` 仍是 Cipherbook 设备间推荐的迁移格式。

Bitwarden 加密 JSON 暂不支持，因为当前桥接不实现 Bitwarden 云端密钥体系。

## 部署与发布风险

- Android Release 当前使用 debug 签名，`applicationId` 仍是 `com.example.cipherbook`。
- Windows 安装包当前没有正式代码签名证书，系统可能显示未知发布者。
- Git 仓库不得包含 `.jks`、`.keystore`、`key.properties`、私钥或真实测试密码库。
- Release 产物应从已验证的同一源码版本构建，并核对版本号、构建号和哈希。
- 正式公开发布前需要唯一 Android ID、独立签名、Windows 代码签名、审计和漏洞响应流程。

## 不在保护范围内

- 已 root / 越狱且被完全控制的设备；
- 操作系统、Flutter 引擎或依赖供应链被攻破；
- 用户主动导出明文、复制密码或截图；
- 用户遗失主密码、设备损坏且没有备份；
- 恶意输入法和无障碍服务读取用户输入；
- 公网暴露的局域网同步端口；
- 未经审计的自定义修改版 APK 或 Windows 二进制。

## 报告安全问题

请勿在公开 Issue 中粘贴密码库、主密码、TOTP 密钥、设备 token 或可复现的真实凭据。
报告方式见仓库根目录的 [`SECURITY.md`](../SECURITY.md)。
